# 검증과 해석 기준

실행형 v0.1.0입니다. 실제 검사 범위는 VALIDATION.ko.md와 GitHub Actions 결과를 함께 확인합니다.

## 의미 있는 확인

- 실제 MCP initialize, tools/list, tools/call을 각각 검사합니다. 서버 시작이나 목록 조회만으로 연결 완료라고 하지 않습니다.
- 작은 수동 정답, 잘못된 입력, 제약 검사, 가능하면 작은 입력의 완전 탐색·참조 비교를 사용합니다.
- 구현과 같은 가정을 복제한 테스트는 함께 틀릴 수 있습니다. 같은 AI의 역할 변경을 독립 검증이라고 하지 않습니다.
- 종료 코드 0과 oracle 결과를 구분합니다. check가 보고한 정답 판정 자체의 신뢰성은 코드를 검토해야 합니다.
- 동일 입력·검사·환경·실행 인자에서 정확성을 통과한 run끼리 비교합니다.
- 샘플 수·측정 구간·원시 값과 한계를 함께 남깁니다. 전체 subprocess 시간은 알고리즘 함수 시간·API·DB·화면 반응 시간과 다릅니다.
- 측정하지 않은 메모리나 최적성은 수치 또는 보장으로 만들지 않습니다.
- 코드·fixture·검사가 바뀌면 새로 확인합니다.

## 실제 자원 제한

동시 job 1개, 전체 deadline 1–120초(기본 제안 30초), warmup 0–3회, 측정 1–10회, stdout/stderr 합계 1MiB입니다. 추적 입력은 32MiB·2048파일, 입력 열거 8192항목, blob 저장소 256MiB로 제한합니다. 큰 데이터는 범위를 명시해 따로 검증해야 하며 작은 샘플 결과를 전체 데이터 보장으로 표현하지 않습니다.

파일·시간·출력 상한은 보안 샌드박스나 OS 전체 메모리 제한이 아닙니다. 제공 환경의 실제 자원 한도를 확인합니다. Windows symlink 제한·하드 종료와 자식 정리의 한계는 현재 도구 계약에 명시했습니다.

## 180분 운영 예시

| 경과 시간 | 목표 |
|---|---|
| 0–15분 | 요구·제약·수용 기준·가정 |
| 15–40분 | 작은 baseline과 수동 정답 |
| 40–100분 | 핵심 사용자 흐름 완성 |
| 100–130분 | 정확성·동일 조건 개선 비교 |
| 130–155분 | 권한·저장·오류·실제 화면 점검 |
| 155–170분 | 최종 코드 재검증·본인 이해 점검 |
| 170–180분 | 필수 파일·저장·제출 확인 |

별도 후속 평가·대기·전체 종료 시각을 따로 계산합니다. AI가 금지된 단계에서 이 도구를 계속 사용하거나 기록 열람을 허용한다고 가정하지 않습니다.
